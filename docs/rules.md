## 已实现的规则语义

- 144 张实体牌：34 种主体牌各 4 张，8 种花牌各 1 张；主体牌和花牌分别保存实体身份。
- 显式种子与确定性牌墙。相同种子、规则版本和动作序列可重放。
- 发牌后起手补花、行牌摸花窗口、选择补花或弃花、杠后补牌。
- 吃、碰、直杠、暗杠、加杠、加杠抢和窗口、自摸和、点炮和、过。
- 响应窗口按和牌优先、碰/杠优先于吃、同优先级取离弃牌者最近座位的规则裁定。
- 普通和牌形、七对、十三幺、全不靠、七星不靠、组合龙的基本结构识别。
- 8 番起和门槛；花分独立记录，不能用于凑起和门槛。
- 点炮与自摸的零和支付：每家 8 分底分，点炮者另付和牌番分；花分计入正式支付。
- 玩家观察隐藏其他玩家暗手和未公开暗杠牌种；合法动作只从该玩家可见状态生成。

当前测试覆盖见 `ocaml/mahjong_core/test/test_core.ml`，包括实体牌守恒、确定性牌墙、结构判和、8 番门槛、Chicken Hand、All Types、第五张实体牌不可成为和牌张、观察隐藏信息、动作目录、结构向听、随机合法对局和启发式完整对局。

## 已采用的数字映射

- 吃：记录为顺子中间牌对应的起始数字，并用实体牌实例构造副露。
- 碰/直杠：弃牌实体从牌河转移到副露，不能同时保留在牌河库存中。
- 暗杠：记录四张实体牌；在终局或本人视角前，观察中的牌种为空。
- 加杠：先在公开副露上留下第四张的待抢杠窗口；无人抢和后再升级为杠并补牌。
- 花牌：起手阶段自动连续补花；摸到花牌时由玩家选择补花或合法弃花。补花与杠补使用不同来源标记，供计番区分。
- 超时/口头流程：当前核心没有网络计时器；数字接口把“过”作为显式动作。未实现的计时裁定不得被默认为某方自动过。

## 当前未完成或不一致的部分

以下内容尚未达到完整 MCR 验收，发布物必须继续标注为阶段一：

- 81 个番种的第三方正向样例已全部命中，但完整排斥、近失、重复计分、同手多解最优性和规范歧义样例尚未系统认证；不能宣称完整算番。
- 特殊牌型的结构识别与对应番种、组合限制仍需系统覆盖；向听仅用于启发式结构距离，不是满足 8 番门槛的精确距离。
- 尚未实现完整 16 手整场、圈风/门风/庄家轮转、累计分和整场名次。
- 发牌采用确定性洗牌和数字发牌顺序，尚未实现骰子决定开牌位置、物理牌墙断开与“一三”实体牌堆流程。此差异不改变牌种数量，但必须保留为未完成项。
- 未提供 WASM/浏览器规则一致性、完整网页牌桌和 GitHub Pages 部署。
- 当前 Python C ABI 的嵌入运行时按进程串行调用；跨线程并发需要独立进程或后续线程安全改造。
- 当前启发性 teacher 不搜索精确番型，只在正式引擎判定合法动作、和牌和结算的前提下使用结构向听/进张。其策略水平不代表完整 MCR 最优策略。

## 验收原则

- 不允许通过减少牌种、动作、番种、门槛或结算流程提高训练吞吐。
- 任何规则修复应同时增加来自规范或明确构造依据的回归样例；未执行的测试、未完成的训练不得写成通过。
- 训练和评估记录必须取自本仓库引擎的真实运行，并明确随机策略、启发式、BC、PPO 和历史模型之间的区别。
