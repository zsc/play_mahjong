## 构建、验收、更新

安装 README 所列固定 OCaml 工具链和 Node 后，从仓库根目录执行：

```sh
cd web
npm ci
npm run prepare:assets
MAHJONG_BASE=/play_mahjong/ npm run build
npm run test:release
npm run stage:pages
```

`stage:pages` 只更新 `docs/` 下列生成内容，保留其他 Markdown 文档：
`assets/`、`runtime/`、`ort/`、`models/`、`licenses/`、`index.html`、`training.json`、`THIRD_PARTY_NOTICES.txt`、`.nojekyll`。
这些产物需要和源码一起提交到 main；`.nojekyll` 让 Pages 直接提供静态文件。
网页不需要被忽略的 Python checkpoint、原始训练集或完整对局日志。
发布包附带第三方许可证，ONNX Runtime JS/WASM 均固定为 1.30.0。

本地已执行生产构建、真实浏览器静态子路径验证：关闭 WebGPU，390×844 视窗无横向溢出，
模型建议、真人出牌、真实训练记录、hash 导航刷新及许可文件加载通过。
训练恢复/导出/评估的针对性 Python 回归 9 项通过，ruff 通过。
本轮复跑原生/WASM、隐藏信息/回放、失败处理 3 项浏览器回归通过；
4 盘 291 次转移与 207 次推理动作一致。证据见 `benchmarks/browser-wasm-parity.json`。
另外直接用普通 HTTP 服务提供将提交的 `docs/`，静态发布测试再次通过；
16 个静态文件逐字节匹配 `web/dist`，合计 15,955,244 字节，见 `benchmarks/pages-release.json`。

GitHub 工作流重新构建并验证源码，在 Actions 中保留静态产物；Pages 使用已提交的 `docs/`。
首次开启：仓库 Settings → Pages → Build and deployment → Deploy from a branch → main → /docs → Save。
之后检查 GitHub 的 Pages 部署状态，再访问目标网址。操作依据：[GitHub 分支发布文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
